# DSAA Case Study — Repository Instructions

## 1. Project Overview

Each group must develop a simple application that applies and implements its assigned **Abstract Data Type (ADT)** using an appropriate data structure representation for a chosen problem or scenario.

Use this repository to maintain and submit the complete source code for your group's application.

## 2. Choose Your Problem and Data Structure

Before implementation:

- Check the Google Sheet provided by the instructor for your group's assigned ADT.
- Add your group members' names to the sheet.
- Identify the data structure representation you will use.
- Choose a problem or scenario that uses the assigned ADT.
- Make sure the chosen data structure is appropriate for the problem.
- Be prepared to explain why the ADT and data structure are a good match.

## 3. Application Requirements

Develop a simple application using a programming language of your choice.

Your application must:

- Provide a graphical user interface (GUI).
- Allow users to enter or provide input.
- Display the resulting output.
- Implement the assigned ADT using an appropriate data structure.
- Demonstrate the ADT and data structure working together to solve the chosen problem.
- Be functional, understandable, and reasonably user-friendly.

## 4. Recommended Repository Organization

Organize your files so that the source code is easy to locate and understand. You may adapt this structure to your chosen language and framework.

```text
repository/
├── README.md
├── INSTRUCTIONS.md
├── src/                 # Application source code
├── assets/              # Images or other application assets, if needed
├── screenshots/         # Optional screenshots of the application
└── docs/                # Optional supporting documentation
```

Do not include passwords, API keys, access tokens, or other secrets in the repository.

## 5. Code and Documentation

- Keep the complete application source code in this repository.
- Use clear names for variables, functions, classes, and files.
- Organize the code so that the ADT implementation and important operations can be identified.
- Add comments where they help explain important logic.
- Ensure the code can be understood during the presentation and code walkthrough.
- Include setup and run instructions in `README.md`, including any required dependencies.

## 6. Onsite Presentation

Each group must deliver an onsite presentation lasting **at least 7 minutes and no more than 10 minutes**. Prepare a PowerPoint slide deck with the following sections.

### A. Introduction

- Give an overview of the chosen problem or scenario.
- Discuss the assigned ADT.
- Discuss the selected data structure.

### B. Algorithm

- Present the algorithm creatively.
- Explain how the ADT is applied to the problem.
- Explain why the chosen data structure is appropriate.

### C. Code Walkthrough

- Include screenshots of your actual source code in the slides.
- Explain how the ADT and data structure are implemented.
- Explain the logic of key functions, operations, and data-handling sections.

### D. Application Demonstration

After the slide presentation:

- Run the application.
- Show sample input and output.
- Explain how the ADT and data structure function within the system.

The case study will be assessed using these criteria:
